---

## Project Rules

1. **PRD is the source of truth** — always follow the PRD. If any requirement conflicts, `docs/PRD.md` takes precedence.
2. **Do not invent new sections** — only build what is specified in the docs.
3. **Leave placeholders** — if information is missing, use placeholder content instead of making assumptions.
4. **Prioritize readability and professionalism** — this site represents a CPA's professional brand.
5. **Build reusable components** — avoid repetitive code; create utility classes and component patterns.
6. **Keep the design responsive** — mobile-first approach, tested at all breakpoints.
7. **No AI slop** — every word must serve credibility. Avoid generic templated phrasing.

---

## Workflow

Before writing any code, read the documentation in this order:

1. **`docs/PRD.md`** — product requirements (source of truth)
2. **`docs/DESIGN.md`** — visual design, layout, and component specifications
3. **`docs/CONTENT.md`** — all copy and content structure
4. **`docs/TASKS.md`** — implementation checklist

Do not begin implementation until you understand the overall objective and information architecture.
